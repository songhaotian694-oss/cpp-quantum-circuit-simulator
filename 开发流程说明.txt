开发流程说明
（基于C++的轻量级量子线路仿真与可追踪优化平台）

编写日期：2026年8月7日
适用范围：本说明描述本项目的开发流程，包括开发环境准备、代码编写、构建、测试、运行与版本管理，适用于全体团队成员。与《项目结构说明.txt》配套阅读。

一、总体流程概述

本项目开发遵循以下基本循环：

设计接口 → 编写代码 → 构建 → 运行验证 → 编写或更新测试 → 提交版本 → 评审合并

各模块按照“明确理论关系—设计数据结构—完成代码实现—编写测试样例—分析测试结果”的顺序推进。基础功能（仿真核心、两类优化规则、可追踪日志）优先完成并验证，再增加界面效果与拓展功能。

二、开发环境准备

1. 编译器：MinGW-w64 或 MSVC，须与所安装 Qt 套件保持一致。
2. CMake：用于生成与执行构建，版本以项目要求为准。
3. Qt：安装桌面端 Qt（Widgets 组件），版本以项目要求为准，所有成员统一。
4. git：用于版本管理，配合 GitHub 远端仓库使用。
5. 环境验证：在全新目录中完成项目配置、编译并运行 Hello 程序与单元测试，至少两台成员电脑可复现，方可认为环境就绪。

三、获取与组织代码

1. 通过 git clone 获取仓库，并在本地建立开发分支。
2. 分支约定：
   - main：主分支，始终处于可构建、可测试状态；
   - develop：当期集成分支；
   - feature/*：功能开发分支，任务完成后合并回 develop；
   - release/1.0：软件著作权与结项对应的基础版本分支。
3. 目录与文件的组织方式见《项目结构说明.txt》，新增文件须放入对应目录。

四、代码编写流程

1. 先编写头文件（.h）声明接口，再编写实现文件（.cpp）完成功能。
2. 一个类拆分为头文件与实现文件两部分；核心模块不依赖 Qt，可在命令行与测试中独立运行。
3. 新增或删除源文件时，同步修改 CMakeLists.txt。
4. 编码规范：
   - 命名、缩进与注释风格保持一致；
   - 禁止遗留调试输出；
   - 核心模块禁止调用 Qt 控件；
   - 全局约定（比特编号、角度单位、容差、随机种子）不得在局部自行解释。

五、构建流程（CMake）

1. 配置：在项目根目录执行 CMake 配置命令（如 cmake -S . -B build），必要时通过 CMAKE_PREFIX_PATH 指定 Qt 安装路径。
2. 构建：执行构建命令（如 cmake --build build），生成目标程序。
3. 构建目标：
   - 核心静态库：供各程序共同链接；
   - 命令行程序：演示与调试核心功能；
   - Qt 界面程序：桌面端图形界面；
   - 测试程序：自动化验证。
4. Qt 在构建中的作用：
   - find_package 定位本机安装的 Qt；
   - uic 工具将 .ui 布局文件转换为可编译代码；
   - moc 工具处理信号槽相关声明；
   - 链接阶段将项目代码与 Qt 库合并。
5. 构建成功后，测试程序应全部通过，方可视为一次有效构建。

六、运行流程

1. 命令行程序：直接运行 build 目录下生成的 exe，通过参数或交互输入线路、参数、随机种子与测量次数，输出状态、概率、优化日志与 CSV 数据。
2. Qt 程序：运行界面 exe；若目标机器未安装 Qt，须将所需 Qt DLL 放置于 exe 同目录，或使用 windeployqt 等工具部署。
3. 实验类运行须固定随机种子，保证结果可复现。

七、测试流程

1. 测试分层：
   - 手算单元测试：1—3 比特已知输入输出，覆盖每个门；
   - 不变量测试：归一化、逆操作恢复、概率非负等；
   - 案例测试：叠加、Bell 态、Deutsch-Jozsa、Bernstein-Vazirani 的理论答案；
   - 优化规则测试：正例、连续触发样例、反例、边界角度与空线路；
   - 随机等价测试：固定种子，随机归一化输入，比较优化前后状态或概率。
2. 随机线路测试不少于 50 条，须保存种子与线路结构，保证失败可复现。
3. 优化等价验证：对同一输入态分别执行优化前后线路，在统一容差（epsilon）内比较最终状态向量或测量概率；仅比较门数量不构成有效验证。
4. 测试失败时，保存版本号、种子、输入态、原线路、优化线路、规则步骤与误差指标。

八、版本管理与提交

1. 提交信息应清楚描述本次修改内容，一次提交对应一个可独立说明的改动。
2. 合并条件：任务描述清楚、测试新增或更新、构建通过、无调试输出、文档同步、复核人实际运行确认。
3. 版本标签：
   - v0.1-summer：暑假竖切版本；
   - v0.4-core：核心功能版本；
   - v0.6-opt：优化功能版本；
   - v0.9-integrated：界面集成版本；
   - V1.0-rc / V1.0-final：基础版发布候选与最终版本。
4. 每个发布标签同时保存编译环境、依赖版本、默认种子、测试摘要与已知限制。

九、文档与记录

1. 接口约定与架构决定写入 docs 目录，变更后同步更新。
2. 实验记录、CSV 字段与使用说明保持一致，由专人负责核对。
3. README.md 中的构建与运行说明须与当前代码状态一致。

十、验收与交付

1. 完成定义（Definition of Done）：
   - 功能：满足任务描述的输入、输出与异常条件；
   - 正确性：新增自动测试，理论答案已记录，回归全部通过；
   - 可复现：固定种子，失败样例可重放，其他电脑可运行；
   - 可维护：核心无 Qt 依赖，命名与全局约定一致；
   - 可说明：接口、日志、说明书与 CSV 字段同步；
   - 可交付：版本号、变更说明、构建说明与已知限制齐全。
2. 发布前须在至少两台电脑上完成构建、运行与测试的双机复现。
3. 软件著作权申请材料须与 V1.0 标签对应的代码与文档一致，并保存提交凭证。

十一、注意事项

1. 提升功能（OpenQASM、部分测量、线路深度、Qiskit 对照等）不得在基础功能完成前挤占主线。
2. 课程考试周自动降载，仅保留缺陷处理与代码合并，不新增功能。
3. 修改统一约定（比特序、接口、日志字段）时，须同步修改全部相关模块与文档，并经全体确认。
